# PFS native plugin lifecycle
Repository root: 666pfs-plugin. Read current/PLUGIN_CURRENT.json, continuity/PLUGIN_REHYDRATION.md, continuity/PLUGIN_LIFECIRCLE.md, continuity/PLUGIN_BACKUP_STATE.md, governance/MANAGED_PLUGIN_BACKUP_ROUND_GOVERNANCE.md and recovery/RESTORE_CONTRACT.md from verified current PFS HEAD. Those current contracts override this reference. Keep exact plugin ID and existing audience/permissions. Plugin Builder is the executable surface; repo source is PFS-owned source/parity/recovery authority; backup child only tracks recovery and never owns live authority.

Every PFS UPDATE must classify plugin impact: NO_PLUGIN_CHANGE_REQUIRED, PLUGIN_UPDATE_REQUIRED, PLUGIN_UPDATE_BLOCKED, PLUGIN_READBACK_PENDING or PLUGIN_PARITY_REPAIR_REQUIRED. Check rehydration, daemon, LifeCircle, CSM, child lifecycle, Scope Map, handoff, backup, triggers, authority, dashboard, continuity and managed-plugin backup-round governance. Do not bump versions without semantic impact. Relevant verified PFS evolution requires governed plugin evolution and backup, subject to actual tooling and permissions.

Before any foreign/private backup-round notice, PFS must preflight all PFS-managed plugins for freshness, source parity, binary parity and development impact. Complete PFS-owned plugin evolution first. Then freeze one stable backup-round manifest and inform LYVRA and CLIC once for that stable round. Their native approval authority remains separate and per-system. A relevant plugin change after round freeze starts a new round.

Before plugin evolution verify PFS HEAD, locks, allowlist, current plugin release and pre-change recovery. Preserve immutable snapshots. Prepare repo source and release snapshot, update existing plugin with expected_release_id, read live release back, compare file lists and actual text/binary bytes, capture real SHA-256/size/entry list, write backup, directly read it back, compare hash, record receipt, update backup child and continuity, freeze, then publish the PFS pointer last. No mutation afterwards in the same update. If interrupted preserve return anchor and exact pending phase. Never label archive availability as verified backup.

PFS may authorize its own plugin backup; foreign system approval is not needed for its own plugin. Foreign backup legs still require their own native authorization. PFS coordinates the round but never self-approves LYVRA or CLIC.

Backup child must be bound only through current PFS child identity governance. Never guess a current child ID or reuse a foreign plugin child. If unresolved, record OPEN instead of inventing a binding. Backup child source bindings must include plugin/release/version, immutable snapshot, fingerprint, text and binary parity, archive SHA-256/size/path/receipt, readback and restore status.
