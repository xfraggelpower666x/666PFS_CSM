# 666PFS VISUAL INTERFACE — internal presentation adapter

Read [authority](../../references/authority.md) and [visual contract](../../references/visual-interface-contract.md) before rendering. Current repository contracts outrank this presentation skill.

This skill is presentation only. It never selects a child, authorizes a write, changes CSM scope, promotes backup/history to Current, resolves a lock, or creates system authority.

Render context-appropriate views for SYSTEMSTART, UPDATE, WEITER, audit, child lifecycle, CSM coordination, backup governance and explicit dashboard requests. Prefer compact visual cards over prose walls when the state is already verified.

Core cards may include:
- PFS / CSM identity and authority
- repository HEAD + Current pointer
- rehydration and return anchor
- daemon / temporal LifeCircle
- child registry + foreground child
- CSM sub-LifeCircle
- scope map + safe edit scope
- plugin runtime / parity
- backup gate + readback
- LYVRA / CLIC handoff intake
- open work, interruptions and obligations
- locks, conflicts and quarantine
- frozen / visual standstill state when execution is intentionally stopped
- next valid continuation

Use only VERIFIED, ABGELEITET, VORGESCHLAGEN, OFFEN, BLOCKIERT, PARTIAL, WRITE_BLOCKED, READBACK_PENDING and CONFLICT_QUARANTINE when supported by evidence. Never fabricate percentages or PASS states.

A frozen/standstill view means presentation of an intentional stop or stable checkpoint only. It MUST NOT imply process completion, release success, write success or pointer publication unless separately verified.

Never expose secrets, tokens, private recovery payloads or signed material.
